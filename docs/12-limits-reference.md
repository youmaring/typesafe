# 모델, 한도, 레퍼런스 수치

이 문서는 설계와 용량 계획에 필요한 수치를 모아 둔 참고용 페이지입니다. 요금과 한도는 공급자 정책에 따라 변경될 수 있으므로 중요한 결정 전에는 공식 [Models](https://docs.typesafe.ai/models) 및 [API reference](https://docs.typesafe.ai/api) 문서를 확인해야 합니다.

## 1. 모델과 alias

| 항목 | 값 |
| --- | --- |
| 현재 안정 버전 | `jev-1.13.0` |
| 기본 alias | `jev-latest` |
| preview alias | `jev-preview` |
| SDK 기본 모델 | `jev-latest` |

alias는 새 모델이 출시되면 다른 버전을 가리킬 수 있습니다. 응답의 `model` 필드에는 실제로 처리한 버전 ID가 들어오므로 로그에 기록해 두는 것이 좋습니다.

임계값을 특정 버전 기준으로 조정했다면 버전 ID를 고정하는 방식을 검토합니다.

```ts
const client = new TypeSafeClient({ defaultModel: "jev-1.13.0" });
```

계정에서 사용 가능한 모델은 다음으로 확인할 수 있습니다.

```ts
const models = await client.models.list();
```

## 2. 입력 형식

| 항목 | 지원 여부 |
| --- | --- |
| 문자열 | 지원 |
| JSON 객체 | 지원 |
| 텍스트 배열 | 지원 |
| 이미지 | 미지원 |
| 오디오 | 미지원 |
| 비디오 | 미지원 |

텍스트가 아닌 입력은 코드에서 먼저 텍스트나 구조화된 필드로 변환한 뒤 `state`에 넣어야 합니다.

## 3. Context 한도

| 항목 | 값 |
| --- | --- |
| 요청 전체 | 64k token |
| `state` + 가장 긴 단일 질문 | 32k token |

주의할 점:

- `state`는 한 번만 전송되고 모든 질문이 이를 공유합니다.
- 질문을 늘리면 전체 예산은 늘어나지만 32k 제한은 가장 긴 질문 하나에만 적용됩니다.
- 한도에 여유가 있어도 관련 없는 내용이 많으면 정확도가 떨어질 수 있습니다.

## 4. 질문 구조 한도

| 항목 | 값 |
| --- | --- |
| Choice 선택지 | 최대 255개 |
| Score 수준 | 최소 2개, 최대 10개 |
| 질문 개수 | 명시적 상한 대신 context 예산으로 제한 |

Score 수준을 10개까지 늘리기 전에 각 단계의 경계를 실제로 구분해 설명할 수 있는지 확인하는 편이 좋습니다.

## 5. 요금

| 항목 | 값 |
| --- | --- |
| 과금 기준 | input token |
| output token | 무료 |
| 가격 | 1M token당 0.042 USD, 1B token당 42 USD |

비용 관리에서 중요한 점은 다음과 같습니다.

- 같은 `state`에 여러 질문을 묶으면 state 토큰을 중복 전송하지 않습니다.
- 질문별로 별도 요청을 보내면 state 비용이 반복 발생합니다.
- 긴 criteria와 예시도 input token에 포함됩니다.

## 6. Rate limit

| 항목 | 값 |
| --- | --- |
| 토큰 처리량 | 초당 250,000 token |
| 요청 수 | 분당 1,200 request |

공식 문서는 이 한도가 공지 없이 조정될 수 있다고 안내합니다. 따라서 다음을 권장합니다.

- 한도를 코드에 고정 상수로 가정하지 않기
- 429 응답에 backoff 적용
- queue와 concurrency 제한 사용
- 사용량 지표 모니터링

## 7. HTTP 오류 코드

| 코드 | 의미 | 대응 |
| --- | --- | --- |
| 401 | API 키 누락 또는 무효 | 키 설정과 회전 확인 |
| 422 | 요청 스키마 오류 | 질문 구조와 필드 확인 |
| 429 | rate limit 초과 | backoff 후 재시도 |
| 529 | 일시적 과부하 | backoff 후 재시도 |

## 8. SDK 기본값

| 항목 | 기본값 |
| --- | --- |
| Node.js | 20 이상 |
| 현재 확인한 SDK 버전 | 0.6.0 |
| base URL | `https://api.typesafe.ai` |
| 시도당 timeout | 10,000 ms |
| 최대 재시도 | 2회 |
| 최초 backoff | 500 ms |
| 최대 backoff | 5,000 ms |
| backoff jitter | 0.25 |
| 재시도 상태 코드 | 408, 429, 500 이상 |
| `Retry-After` 반영 | 사용 |
| 서버 지정 재시도 대기 상한 | 60,000 ms |
| 브라우저 실행 | 기본 차단 |
| 기본 log level | `warn` |

timeout은 전체 재시도 합계가 아니라 각 시도에 적용됩니다.

## 9. 환경변수

| 이름 | 용도 |
| --- | --- |
| `TYPESAFE_API_KEY` | 인증 키 |
| `TYPESAFE_BASE_URL` | API 주소 변경 |
| `TYPESAFE_DEFAULT_MODEL` | 기본 모델 |

코드에서 직접 지정한 값이 환경변수보다 우선합니다.

## 10. 언어 지원

- 영어가 주 학습 언어이며 정확도가 가장 높다고 안내됩니다.
- 한국어를 포함한 CJK도 입력할 수 있지만 정확도가 더 낮을 수 있습니다.
- 비영어 업무에서는 자체 평가셋으로 검증한 뒤 임계값을 정하는 것이 좋습니다.

## 11. 용량 계획 예시

월 100만 건, 건당 평균 700 input token 가정:

```text
총 토큰 = 1,000,000 * 700 = 700,000,000 token
비용    = 700 * 0.042 USD = 29.4 USD
```

같은 state에 질문을 추가하면 추가 비용은 질문 토큰만큼만 늘어납니다. 반면 질문마다 요청을 나누면 state 토큰이 요청 수만큼 반복됩니다.

실제 계획 시 확인할 항목:

- use case별 평균 state 크기
- 질문 세트의 토큰 크기
- 피크 시간대 초당 요청 수
- 재시도로 발생하는 추가 요청
- 평가와 회귀 테스트에 사용하는 토큰
