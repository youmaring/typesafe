# TypeSafe AI와 Jev란 무엇인가

## 1. TypeSafe AI의 역할

TypeSafe AI는 비정형 텍스트를 소프트웨어가 바로 사용할 수 있는 구조화된 판단값으로 바꾸는 서비스입니다.

일반적인 LLM 사용 방식은 다음과 같습니다.

```text
프롬프트 작성
  -> 자유로운 텍스트 생성
  -> JSON 형식 준수 여부 확인
  -> 파싱
  -> 누락된 값과 잘못된 값을 복구
  -> 업무 로직 실행
```

TypeSafe의 방식은 다릅니다.

```text
판단 대상 state 작성
  -> 답의 형태를 Choice / Score / Noul로 제한
  -> 구조화된 답과 확률 수신
  -> 일반 코드에서 분기와 정책 실행
```

즉, Jev는 문장을 잘 쓰는 모델이 아니라 애플리케이션 안에서 사용할 의미 판단 primitive를 제공하는 모델입니다.

## 2. Jev란 무엇인가

Jev는 TypeSafe의 System One 모델입니다. 사람이 충분한 정보를 보고 빠르게 판단할 수 있는 좁고 구체적인 문제를 다루는 데 적합합니다.

적합한 질문:

- 이 고객 문의는 어느 부서가 담당해야 하는가
- 이 문장은 환불을 요구하는가
- 이 사용자의 불만 정도는 어느 수준인가
- 이 검색 결과는 질의와 관련 있는가
- 이 문서가 정책을 위반할 가능성이 있는가

적합하지 않은 요청:

- 이 문제를 분석해서 최선의 해결책을 긴 글로 작성하라
- 다음 행동을 스스로 결정하고 외부 서비스를 호출하라
- 여러 문서를 읽고 정확한 합계를 계산하라
- 복잡한 날짜 조건을 계산하라
- 사용자에게 보낼 자연스러운 답장을 작성하라

## 3. LLM, Agent, Jev의 차이

### 생성형 LLM

입력 뒤에 올 자연어 또는 코드를 생성합니다.

잘하는 일:

- 답변 작성
- 요약
- 번역
- 코드 생성
- 복잡한 설명

주의할 점:

- 결과 형식이 흔들릴 수 있음
- 존재하지 않는 값을 생성할 수 있음
- 자유도가 높아 업무 코드의 직접 입력으로 쓰기 어려울 수 있음

### Agent

모델이 반복적으로 다음 행동을 결정하고 도구를 호출합니다.

잘하는 일:

- 탐색적 작업
- 사람이 감독하는 반복 작업
- 여러 도구를 사용한 문제 해결

주의할 점:

- 반복 횟수가 늘수록 오류 경로가 많아짐
- 권한과 부작용 관리가 중요함
- 동일 입력에서 행동 경로가 달라질 수 있음

### Jev

개발자가 정한 답의 공간 안에서 빠른 의미 판단을 수행합니다.

잘하는 일:

- 분류
- yes/no 탐지
- 순서형 평가
- 라우팅용 특징 생성
- 검색 결과 평가
- confidence 기반 자동화

제한:

- 텍스트를 생성하지 않음
- 스스로 다음 행동을 정하지 않음
- 계산기나 날짜 엔진이 아님
- 업무 부작용을 직접 실행하지 않음

## 4. 가장 중요한 아키텍처 원칙

### 코드가 전체 흐름을 소유해야 합니다

Jev에게 다음과 같은 요청을 보내지 않는 것이 좋습니다.

```text
고객 문의를 분석하고 필요한 처리를 모두 결정해줘.
```

대신 필요한 판단을 나눕니다.

```text
1. 담당 부서는 어디인가
2. 환불을 명시적으로 요청했는가
3. 긴급성을 표현했는가
4. 불만 정도는 어느 수준인가
```

그리고 코드는 결과를 조합합니다.

```ts
if (department.confidence < 0.6) {
  return routeToHumanReview();
}

if (department.choice === "billing" && refundRequested.noul >= 0.8) {
  return routeToBilling({ refundLikely: true });
}
```

이 방식의 장점:

- 어떤 판단이 최종 결과에 영향을 줬는지 확인 가능
- 업무 정책을 코드 리뷰할 수 있음
- 가중치와 임계값을 모델 프롬프트와 분리 가능
- 확실하지 않은 결과를 명시적으로 중단 가능
- 테스트를 API 호출과 분리 가능

## 5. Jev가 필요한지 판단하는 기준

다음 질문에 대부분 예라고 답할 수 있으면 적합할 가능성이 높습니다.

- 입력은 자연어 또는 텍스트가 포함된 JSON인가
- 출력 후보를 미리 정의할 수 있는가
- 사람이라면 관련 정보를 보고 빠르게 판단할 수 있는가
- 정답 대신 확률 분포가 업무에 도움이 되는가
- 낮은 확률 또는 confidence를 별도 경로로 보낼 수 있는가
- 최종 행동을 코드가 담당할 수 있는가

다음 상황은 다른 도구가 더 적합할 수 있습니다.

- 정확한 수치 계산: 일반 코드
- 문자열 패턴 검색: 정규식 또는 파서
- 날짜 정렬: 날짜 라이브러리
- 자유로운 답변: 생성형 LLM
- 전체 자료 검색: 검색 엔진 또는 벡터 검색
- 장기 계획과 도구 사용: agent 구조

## 6. 대표 적용 영역

### 고객 지원

- 문의 유형 Choice
- 환불 요청 Noul
- 불만 수준 Score
- confidence가 낮으면 사람 상담원

### 문서 처리

- 문서 유형 Choice
- 필수 내용 포함 여부 Noul
- 품질 또는 위험 수준 Score

### RAG

- 질의 관련성 Noul
- 질의와 모순되는지 Noul
- prompt injection 위험 Noul
- 통과한 passage만 생성형 모델에 전달

### 함수 호출

- 함수 이름 Choice
- 제한된 인자 Choice
- confidence 기준 충족 시에만 실행
- 인증과 권한은 별도 코드 검사

### 검색과 추천

- 1차 검색 결과 각각에 관련성 Noul
- 여러 Score를 조합해 순위 계산
- 낮은 확률 결과 제거

## 7. 도입 시 기대해야 하는 작업

TypeSafe를 연결한다고 바로 안정적인 자동화가 만들어지는 것은 아닙니다. 다음 작업이 필요합니다.

1. 실제 use case를 하나 선택합니다.
2. 입력과 정답이 있는 평가 데이터를 준비합니다.
3. 질문을 원자적으로 나눕니다.
4. criteria로 경계를 설명합니다.
5. 확률과 confidence 분포를 관찰합니다.
6. 자동 처리와 사람 검토 임계값을 정합니다.
7. 모델 버전과 질문 버전을 기록합니다.
8. 실제 결과로 반복 보정합니다.

핵심은 모델 호출보다 판단 구조와 평가 체계를 설계하는 것입니다.
